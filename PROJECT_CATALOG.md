## How to volunteer

Comment on the relevant issue with:

```text
GitHub username:
Skills / relevant experience:
Project or deliverable I want to own:
Implementation plan:
Availability:
Questions / blockers:
```

Wait for a maintainer to confirm the scope and assign the issue before starting. If an issue is already assigned, do not begin parallel work without approval and a clear split of deliverables.

## Project levels

- **Beginner:** guided documentation, starter notebooks, small fixes, and simple interfaces.
- **Intermediate:** independent features, integrations, data pipelines, and model evaluation.
- **Advanced:** architecture, performance, deployment, security, and multi-module engineering.
- **Research:** reproducible experiments, benchmarks, ablations, and paper implementations.

See [CONTRIBUTOR_PROGRAM.md](./CONTRIBUTOR_PROGRAM.md) for the full program, mentorship model, progress process, and recognition standards.

## For maintainers

Before publishing a new opportunity:
1. Check for duplicates and existing PRs.
2. Write a clear problem statement and non-goals.
3. Add deliverables and observable acceptance criteria.
4. Set a realistic level and prerequisites.
5. Confirm a mentor/reviewer for beginner work.
6. Confirm dataset, privacy, licensing, and security constraints.
7. Add labels and link related work.
8. Keep this catalog synchronized when the intake list materially changes.

Do not publish unconfirmed deadlines, rewards, certificates, or event details.
